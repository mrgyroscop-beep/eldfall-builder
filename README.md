# Calad Guild

Приватный билдер ростеров Eldfall Chronicles и журнал очной партии для двух игроков.

## Запуск

Node.js ≥22.13; `npm ci`, `npm run dev`. Откройте http://localhost:3000 и нажмите «Войти через ChatGPT». В локальной среде Sites использует тестового пользователя Seedy. Не публикуйте dev-сервер наружу.

`npm run check` выполняет TypeScript, lint, доменные и D1-интеграционные тесты, затем production-сборку. Сгенерированные шадсн-компоненты исключены из lint; собственные компоненты, сервис и тесты проверяются. React Compiler не включён; его экспериментальная lint-проверка отключена только для клиентского экрана с post-SSR гидратацией черновика.

## Что умеет

- Каталог: 63 профиля, фильтры, классы, инвентарь, способности, магия и источники.
- Форматы 65/85/произвольный; лидер, нейтралы, копии моделей, 44 уникальных улучшения из 54 карточек v1.6, выбор опций и памятка заклинаний.
- Валидация бюджета, фракции, 10 моделей, лимитов, лидера, слотов/ограничений улучшений, школ и стихий. Named Characters и Monster factions проверяются с April 2026 errata.
- Серверные ростеры; локальный несохранённый черновик; ссылки просмотра/редактирования; версии и восстановление копии.
- Отдельные RU/EN настройки интерфейса и данных. Переводы названий черновые, статус каждого хранится отдельно. Текст способностей пока английский с понятными внутренними ссылками.
- JSON импорт/экспорт, печатный A4 через системную печать → PDF, резервная копия всех видимых сохранённых ростеров.
- Матч: приглашение ссылкой/кодом, два участника, одинаковый формат, двойное подтверждение, неизменяемые снимки ростеров; инициатива, раунды, HP/AP/mana, состояния, VP, отмена, пауза, итог и журнал событий.
- Сервер — источник истины. Проверка ревизии предотвращает потерю изменений. Второй игрок видит изменения с задержкой до двух секунд плюс сеть.

## Границы

Это помощник для игры **на столе**, не автоматический симулятор боя. Игроки разрешают броски, порядок активаций, призыв, условные эффекты улучшений и завершение состояний. Раунд не сбрасывает ресурсы автоматически. Числовые базовые бонусы улучшений показаны, замены оружия и условные эффекты — текстом карточки. Не обещается полная автоматическая турнирная проверка любых специальных сценариев.

## Данные и обновления

`npm run data:import` сохраняет новый исходный снимок, проверяет структуру/связи и пишет diff в `data/versions`. Просмотрите diff. Только после проверки выполните `npm run data:import -- --publish`, тесты и новый деплой. Ошибка импорта не трогает текущий набор; публикация локального JSON атомарная. Снимки неизменяемые. Версия включает хеш источника, улучшений и версии нормализации.

Основной источник: https://guildhall.eldfall-chronicles.com/. Официальные правила и April 2026 errata: https://eldfall-chronicles.com/pages/resources. Улучшения импортированы отдельным проверенным скриптом из карточек v1.6; не из старых цен в книге.

При первом сохранении набор архивируется в D1. Ростер хранит конкретную версию, матч — копию профилей и улучшений. Автоматическое обновление старых ростеров не выполняется. Для обновления создайте новый ростер с актуальным набором.

## Резервирование / восстановление

1. Каждое серверное сохранение автоматически создаёт неизменяемую ревизию в `roster_versions`. «Мои ростеры → Версии → Восстановить копию» открывает старую редакцию без перезаписи оригинала.
2. «Резервная копия» скачивает JSON с ростерами. Храните его отдельно от сервиса. «Импорт / восстановление» создаёт новые записи; чужие записи никогда не перезаписываются.
3. Для полного аварийного восстановления БД нужен также архив версий справочника из исходного репозитория и экспорт D1. Приложение не имеет полномочий на администрирование БД провайдера.
4. Матч восстанавливается при повторном открытии из последнего серверного состояния. Отдельный append-only журнал сохраняет снимок изменяемого состояния после каждого действия; JSON журнала можно скачать.

Данные тестов создаются в изолированной временной D1 через Miniflare, не в production. Проверены восстановление копии, повторное подключение и конфликт двух одновременных обновлений.

## Приватность и публикация

Sites владеет внешней аутентификацией, HTTPS и D1. API доверяет только переданному платформой `oai-authenticated-user-id` и проверяет права для каждой записи. Секретные ссылки содержат случайную capability в URL-фрагменте; сервер хранит SHA-256. Не передавайте edit/invite ссылки посторонним. Ссылка не обходит внешнюю политику доступа сайта.

Первый запуск — owner-only. Второму игроку требуется отдельный разрешённый аккаунт в политике Sites. На текущем аккаунте внешние приглашения Sites отключены; для игрока вне рабочего пространства понадобится доступный механизм private sharing либо другой хостинг с allowlist. Публичный доступ не включался.

Деплой: `npm run check`, commit/push в привязанный Sites репозиторий, упаковка `dist` штатным Sites helper, сохранение версии, private deploy. `.openai/hosting.json` содержит только идентификатор проекта и логические привязки; секретов в репозитории нет. Миграции — `drizzle/`.

## Архитектура

React / TypeScript + Vinext App Router → `/api/guild` → независимый `lib/service.ts` → подготовленные SQL-запросы D1. Движок `lib/game.ts` и `lib/upgrades.ts` не зависит от UI. `lib/validation.ts` проверяет входящие ростеры и справочник. Перенос на другой Workers-хостинг требует заменить только внешнюю аутентификацию и привязку D1. Альтернатива: Node + SQLite/Postgres с адаптером хранилища и закрытым входом.

Основные таблицы: `datasets`, `rosters`, `roster_versions`, `matches`, `match_events`. Изменение матча и запись события происходят одной D1-транзакцией; `UPDATE … WHERE revision=?` и `changes()=1` исключают ложные события проигравшего конкурирующего запроса.

Жизненный цикл: локальный черновик ростера → ожидание соперника → подтверждение обоими → активен ↔ пауза → завершён (только чтение). Наблюдатель не изменяет матч; игрок меняет только собственные ресурсы; раунд продвигает сторона с инициативой; общую инициативу можно передать; отменить можно только своё последнее изменение до чужого следующего действия.

## Оставшиеся вопросы к владельцу

- Какому аккаунту нужен доступ второго игрока и принадлежит ли он тому же рабочему пространству?
- Какие переводы терминов считать окончательными? Сейчас все русские названия помечены как draft.
- Нужны ли полная автоматизация призывов, эффектов оружия и скрытых схем? Это расширение поверх текущего настольного трекера.

Браузерный визуальный прогон на реальных телефонах и печать в PDF не выполнялись без отдельного запроса. Проверены сборка, SSR-разметка, responsive/print CSS и серверная логика; ручная приёмка интерфейса остаётся отдельным шагом.
